## 目标

把 BridgeCN 从"看起来像网页的演示"升级到"客户可以真的使用、数据真实、流程强制按顺序走"的产品。当前缺口很明确：除了 Project Builder，所有 AI 模块仍走 `placeholder.ts`（基于项目上下文模板拼字符串，不是真实分析）；Checklist 不持久化；流程没有强制顺序，用户可以跳着点；Reports 是从最近 job 拼出来的，不是真正生成的报告。

下面是一次性把这四块全部做到"真能用"的方案。

---

## 1. 真实 AI 生成（替换 placeholder）

新建一个真实 provider：`src/lib/ai/providers/lovable.ts`，通过 Lovable AI Gateway 调 `google/gemini-3-flash-preview`，并新增 4 个 server function（`createServerFn`，放在 `src/lib/ai/generate.functions.ts`）：

- `generateMarketInsight` — 输入 ProjectContext + Knowledge Base，输出严格 JSON schema：`{ summary, kpis:{marketSize,cagr,aov,penetration}, keywords[], regions[], sources[], confidence }`
- `generateConsumerInsight` — 输出 `{ personas[], painPoints[], purchaseDrivers[], channels[], summary }`
- `generateLocalization` — 输入源文案 + 目标市场 + 品牌 tone，输出 `{ items[{source,target,note}], insights, compliance[], scores }`
- `generateLaunchChecklist` — 基于项目 + 已生成的 market/consumer 结果，输出该项目专属的 phases/items（不是通用模板）

要点：
- 全部走 `Output.object({ schema: z.object(...) })` 拿 schema 化 JSON，避免 LLM 自由发挥导致字段缺失。
- `placeholder.ts` 保留为离线 fallback：网络/credits 失败时 catch 住，降级到 placeholder，并在 UI 用 badge 标 "Offline preview"。
- Provider 选择：`use-ai-job.ts` 默认改成 `lovable`，开发环境 env flag 可切回 placeholder。
- 把当前项目的 Knowledge Base 全字段（公司/品类/产品/竞品/目标市场/受众/品牌故事/tone/营销文案/关键词/社媒）打包进 prompt，让模型输出真正贴合该项目的内容。
- 错误处理：429 → toast "Rate limited, retry later"；402 → toast "Credits exhausted" + 链接到 Settings → Plans & credits；其它 → 显示原始 error.message。

## 2. Checklist 真正持久化

新建表 `project_checklist`：

```text
id uuid pk
project_id uuid fk projects on delete cascade
item_key text          -- 由 generateLaunchChecklist 返回，稳定 key
checked boolean default false
checked_at timestamptz
checked_by uuid fk auth.users
unique(project_id, item_key)
```

- RLS：只允许同 workspace 的 member 读写（通过 projects.workspace_id 校验）。
- GRANT SELECT/INSERT/UPDATE/DELETE 给 authenticated。
- Server functions：`listChecklist(projectId)`、`toggleChecklistItem(projectId, itemKey, checked)`。
- `launch-checklist.tsx`：复选框接真实 state，进度按 `checked/total` 计算；首次进入若无数据自动跳一次 `generateLaunchChecklist`。

## 3. 强制按顺序的工作流

当前 `workflow.ts` 已经定义了 stage 顺序（research → consumer → localization → launch → reports），但没有"门禁"。新增 `useStageGuard`：

- 在 `projects` 表新增列 `stage_progress jsonb default '{}'`，形如 `{ research: "done", consumer: "in_progress", localization: "locked" }`。每次对应模块的 AI job 成功完成，server function 自动写入 `done`，并把下一个 stage 从 `locked` 翻成 `available`。
- 每个 stage 页面（Market / Consumer / Localization / Launch / Reports）在 mount 时检查 `stage_progress`：
  - 如果当前 stage 是 `locked` → 显示 "Complete previous step first" 空态 + CTA 跳回未完成的那一步，禁用所有 Generate 按钮。
  - 如果是 `available` → 显示 Generate CTA。
  - 如果是 `done` → 显示结果 + "Regenerate" + "Next: <下一步名>"。
- 侧栏导航：未解锁的菜单项加锁图标 + disabled cursor + tooltip "Unlock by completing <prev>"。
- `WorkflowFooter` 的 Next 按钮：只在当前 stage 是 `done` 时才 enabled。
- 项目创建完成后自动跳 `/projects/$projectId`，KB 卡片下方给醒目的 "Start: Generate Market Insight" 主 CTA。

## 4. Reports 真正生成

不再从最近一次 job "拼"报告，而是新增 `generateReport` server function：

- 入参：projectId
- 内部读取该项目的 market/consumer/localization 三份 job 的 `output_data`，连同 ProjectContext 一起喂给 Gemini，输出结构化 `{ executiveSummary, marketSection, consumerSection, localizationSection, launchPlan, risks[], recommendations[] }`。
- 写入 `ai_jobs`（module=`report`）+ 一行 `reports` 表（id, project_id, title, generated_at, summary, payload jsonb）。
- `/report/$reportId` 渲染该 payload；Share = `navigator.clipboard.writeText(window.location.href)`；Export PDF = `window.print()` + 一套打印 CSS（保留品牌 header、移除侧栏、A4 分页）。
- Reports list 从 `reports` 表读，不再从 `ai_jobs` 倒推。

## 5. i18n 与空态收尾（避免"假网页"观感）

- 所有硬编码英文（projects 详情页/列表的 Edit/Duplicate/Archive/Delete/toast、Report 的 "Generated by BridgeCN AI"、Consumer/Report 的提示文案）入 i18n key。
- 浏览器原生 `confirm()` 全部替换为 shadcn `AlertDialog`。
- 每个模块结果区在无数据时显示统一 EmptyState 组件（图标 + 一句话 + 主 CTA），不再出现"卡片消失"或"永远 0%"。
- Confidence 从 "96%" 改成 High / Medium / Low + tooltip 说明依据。

---

## 技术要点（给开发用）

- 新 server functions 全部放在 `src/lib/ai/*.functions.ts`（client-safe 路径，不放 `src/server/`）。读 `process.env.LOVABLE_API_KEY` 只在 `.handler()` 内。
- Provider 实现参考 `ai-sdk-lovable-gateway` 知识卡：`createOpenAICompatible({ name:"lovable", baseURL:"https://ai.gateway.lovable.dev/v1", headers:{ "Lovable-API-Key": key, "X-Lovable-AIG-SDK":"vercel-ai-sdk" } })`，用 `generateText` + `Output.object`。
- 所有写操作（checklist toggle、stage_progress 更新、reports insert）走 `.middleware([requireSupabaseAuth])`，RLS 按 workspace 成员校验。
- 数据库改动统一一次 migration：新表 `project_checklist`、新表 `reports`、`projects.stage_progress` 列；每个新表都带 GRANT + RLS + 策略。
- 流程门禁不在前端硬写：`stage_progress` 是真实状态，前端只读它决定 UI；这样刷新页面、跨设备、跨用户看到的解锁状态一致。

## 执行顺序

1. DB migration（reports、project_checklist、stage_progress）
2. Lovable AI provider + 4 个 generate server functions（替换 placeholder 主路径）
3. 各模块页接入真实生成 + 错误处理 + Offline fallback badge
4. Stage guard（locked / available / done）+ 侧栏锁 + Footer Next 门禁
5. Checklist 真实勾选 + 持久化
6. Reports 真实生成 + 打印样式
7. i18n 清扫 + AlertDialog 替换 + EmptyState 统一

完成后：建一个 "Jeju Samdasoo / Beverage / Natural Mineral Water" 测试项目，端到端跑一次 Market → Consumer → Localization → Launch → Report，验证：①每一步内容真的关于矿泉水而不是模板；②上一步未完成时下一步是锁的；③刷新后勾选/进度都还在；④Report 可以打印成 PDF 也能复制链接。
